## 1. 系統概述

### 1.1 系統目的與範圍
視覺化網頁系統旨在為 Line-Bot 官方帳戶管理員提供後台數據視覺化工具。系統讀取遠端 PostgreSQL 資料庫中的 Line-Bot 歷史數據，處理並呈現用戶統計、趨勢和受眾分群。系統不處理 Line-Bot 核心邏輯（如聊天訊息），僅限於數據讀取和分群通知。

- **主要功能模組**：用戶註冊與認證、數據視覺化儀表板、受眾分群管理、數據匯出。
- **技術架構**：前端使用 React 框架，後端 API 使用 Python Flask。資料庫：遠端 PostgreSQL（Line-Bot 數據，透過預先定義好的資料庫函式進行查詢；分群規則透過生成Line message通知更新）、本地 SQLite（系統數據，如用戶權限）。外部服務：Google OAuth（註冊）。遠端Line-Bot系統：用於接收Line message通知分群更新。

### 1.2 目標用戶與權限
- 主要用戶：企業主、管理者。
- 權限系統：基於角色。管理員負責管理系統用戶（新增/刪除 Gmail 白名單）與網站設定（OA Configs）；普通用戶則根據被授權的 `oa_configs` 存取對應數據。權限存儲在本地 SQLite 的 `users` 表中。登入後，用戶僅見允許的帳號數據。


### 1.3 假設與依賴
- 參考 FRD 第 2 節。系統假設遠端資料庫始終可用，且提供指定的資料庫函式以供後端應用程式呼叫。每個遠端OA系統用相同格式儲存資料，提供OA名稱和URL即可存取。
- **描述**：使用折線圖在儀表板格式中顯示選定時間區間的用戶人數和新加入用戶。數據來源為遠端PostgreSQL函式查詢。用戶可選擇區間（週、月、年）和資料類型（訊息或加入好友）。前端負責基於查詢返回的所有群組數據進行分群顯示。
- **輸入**：時間區間選擇、資料類型選擇。
- **輸出**：顯示用戶人數和加入的互動折線圖儀表板。API 返回 JSON 格式：`[{"category": "Message", "tag": "tag1", "count": 10}, ...]`。
- **優先級**：高（核心功能，先實現）。

## 2. 詳細功能描述

### 2.1 FR-001: 用戶認證
- **功能細節**：系統不開放公開註冊。用戶透過 Google OAuth 進行登入。前端取得 Google Token 後，傳遞至後端進行驗證。後端確認該 Google 帳號 (Gmail) 是否已預先登記在本地資料庫的 `users` 表中。若存在，則視為合法用戶，回傳 JWT；若不存在，則拒絕存取。
- **輸入處理**：來自前端的 Google Token。
- **輸出**：登入成功時返回 JWT token；失敗時返回授權錯誤。
- **錯誤處理**：無效的 Google token 或用戶未預先登記時，回傳明確的錯誤訊息。
- **UI 設計**：僅有登入頁面，包含 Google 登入按鈕。
- **數據流**：前端 Google 登入 → 前端取得 token → 呼叫後端 API → 後端驗證 token 並查詢本地 DB → 回傳 JWT 或錯誤。
- **優先級**：中（視覺化完成之後再開發）。

### FR-002: 用戶人數和加入趨勢視覺化
- **描述**：使用折線圖在儀表板格式中顯示選定時間區間的用戶人數和新加入用戶。數據來源為遠端PostgreSQL函式查詢。用戶可選擇區間（週、月、年）和資料類型（訊息或加入好友）。前端負責基於查詢返回的所有群組數據進行分群顯示。
- **輸入**：時間區間選擇、資料類型選擇。
- **輸出**：顯示用戶人數和加入的互動折線圖儀表板。API 返回 JSON 格式：`[{"category": "Message", "tag": "tag1", "count": 10}, ...]`。
- **優先級**：高（核心功能，先實現）。

### FR-003: 用戶回應趨勢視覺化
- **功能細節**：儀表板頁面將以 Material-UI 表格形式顯示關鍵字排名。此表格將包含「排名」、「關鍵字」和「次數」三欄。查詢遠端 PostgreSQL 函式，依據選定的時間區間、可選的`tag`來統計關鍵字頻率。為了版面整潔，關鍵字欄位設有最大寬度，若內容過長將以「...」省略，使用者可透過滑鼠懸停在該欄位上來查看完整的關鍵字。顯示的資料筆數由`limit`參數控制。
- **輸入處理**：時間區間（日期範圍）、可選的`tag`群組過濾器、可選的`limit`筆數限制。
- **輸出**：一個表格，顯示指定筆數的紀錄，包含排名、關鍵字及出現次數。API 返回 JSON 格式：`{"data": [{"keyword": "關鍵字1", "count": 20}, ...]}`。
- **錯誤處理**：參考 FR-002。
- **UI 設計**：與 FR-002 整合，新增一個三欄式（排名、關鍵字、次數）的關鍵字表格區塊。
- **數據流**：前端帶有 `tag` 與 `limit` 等參數請求 API → API 查詢遠端 PostgreSQL 函式 → 返回指定筆數的排名數據 → 前端直接渲染表格。

### 遠端PostgreSQL資料庫欄位描述
遠端PostgreSQL資料庫將提供函式（非直接表查詢），用於存取Line-Bot歷史數據。系統使用遠端PostgreSQL函式進行數據查詢。以下為主要函式返回數據結構：

**get_events_count_by_category_and_tag 函式**：
- **返回格式**：JSON 陣列，每個元素為物件，包含以下欄位：
  - **category**：類別名稱（類型：字串，例如 "Message", "Follow"）。
  - **tag**：標籤名稱（類型：字串，例如分群名稱或時間標籤）。
  - **count**：事件數量（類型：整數）。

**get_keyword_ranking 函式**：
- **輸入參數**：`start_time`, `end_time`, `tag`, `limit`
- **返回格式**：JSON 陣列，每個元素為物件，包含以下欄位：
  - **keyword**：關鍵字（類型：字串）。
  - **count**：出現次數（類型：整數）。

視覺化功能（FR-002和FR-003）將基於這些函式返回的數據，對不同期間顯示使用者人數變化趨勢或關鍵字排名。

### 2.4 FR-004: 受眾分群管理
- **功能細節**：分群頁面允許設定自動規則（訊息類型 + 關鍵字）。從遠端更新群組列表，透過新增功能呼叫遠端進行群組更新。當本地已做修改但未進行遠端更新時，UI顯示「需按鈕完成更新」和「回復成現有狀況」兩個按鈕。透過生成Line message（JSON格式與Line API標準spec相同）通知遠端Line-Bot系統，由其使用Line API進行群組和分群法則的更新。通知遠端，讓遠端自行運用。遠端系統會基於關鍵字進行各種驅動，包含調用用戶分群。訊息類型包括「加入好友」「按下按鈕」「輸入訊息」，後兩種有訊息細節。
- **輸入處理**：群組名稱、規則條件（訊息類型 + 關鍵字，例如訊息類型「輸入訊息」關鍵字「運送」）。
- **輸出**：群組列表頁面，顯示規則和用戶數（遠端PostgreSQL function計算）。更新成功後刷新列表。
- **錯誤處理**：無效規則顯示錯誤；通知失敗回滾。
- **UI 設計**：分群管理頁面，表格顯示群組規則，新增/編輯模態框。
- **數據流**：前端操作 → 本地修改 → 顯示更新按鈕 → 確認後生成Line message通知遠端Line-Bot系統 → 遠端系統使用Line API更新 → 返回確認。
- **優先級**：中（實現後視覺化）。

### 2.5 FR-005: 數據匯出
- **功能細節**：在視覺化頁面添加匯出按鈕，生成 CSV 或 PDF 報告（使用 jsPDF）。
- **輸入處理**：格式選擇（CSV/PDF）、當前視圖數據。
- **輸出**：下載文件。
- **錯誤處理**：生成失敗顯示錯誤。
- **UI 設計**：按鈕在儀表板底部。
- **數據流**：前端請求 → API 生成文件 → 返回 Blob → 下載。
- **優先級**：低。

## 3. 數據模型

### 3.1 本地 SQLite 資料表
以下資料表將儲存於後端應用程式本地的 **SQLite** 資料庫中，用於管理系統自身的用戶與設定。

- **users**：id (PK), email, role ('admin'/'user'), allowed_oa_configs (JSON list of oa_config IDs), created_at。
- **pages**：id (PK), name (unique), description。
- **oa_configs**：id (PK), page_id (FK to pages.id), oa_name, db_url (遠端DB URL), other_settings (JSON)。

### 3.2 遠端 PostgreSQL 函式（參考假設）
- **get_events_count_by_category_and_tag**：輸入參數（start_time, end_time, categories, group_unit），返回 JSON 陣列格式的事件統計數據。
- **get_keyword_ranking**：輸入參數（start_time, end_time, tag, limit），返回 JSON 陣列格式的關鍵字排名數據。

## 4. 接口規範

### 4.1 API 端點示例（RESTful，使用 Python Flask）
- POST /auth/google-login：使用 Google Token 進行登入驗證。
- GET /dashboard/user_trend?period=week&start_date=2023-01-01&end_date=2023-01-07&data_type=message：獲取用戶數據（依權限過濾帳號）。
- GET /dashboard/responses?start_date=2023-01-01&end_date=2023-01-07&tag=some_tag&limit=50：獲取關鍵字數據。
- POST /groups：新增群組（呼叫遠端更新）。
- PUT /groups/{id}：編輯群組規則（通知遠端系統）。
- GET /admin/users：取得用戶列表。
- POST /admin/users：新增用戶（白名單）。
- DELETE /admin/users/{id}：刪除用戶。
- GET /admin/oa_configs：取得 OA 設定列表。
- POST /admin/oa_configs：新增 OA 設定。
- PUT /admin/oa_configs/{id}：更新 OA 設定。
- DELETE /admin/oa_configs/{id}：刪除 OA 設定。

### 4.2 外部 API
- Google OAuth：使用 google-auth-library。
- 遠端Line-Bot系統：接收Line message通知分群更新（JSON格式與Line API標準spec相同）。

## 5. 測試案例

- **FR-001**：註冊新用戶，郵件連結點擊重定向成功頁面自動驗證；登入檢查權限（普通用戶僅見指定帳號）。
- **FR-002**：選擇週區間，驗證圖表數據正確；無權限帳號拒絕查詢。
- **FR-003**：篩選特定tag，檢查關鍵字排名是否正確。
- **FR-004**：新增群組呼叫遠端，本地修改顯示更新按鈕，確認後通知遠端系統成功。
- **FR-005**：匯出 CSV，驗證文件內容；邊界測試：空數據匯出。

## 6. 非功能實現

- **性能**：優化 DB 索引。
- **安全性**：HTTPS、數據加密、JWT 過期 1 小時。
- **可用性**：響應式設計（Material-UI）。

本規範基於 FRD，作為開發指南。變更需經審核。
