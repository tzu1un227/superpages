## 1. 介紹

### 1.1 目的
視覺化網頁系統（Visualization Web System）的目的是為Line-Bot官方帳戶管理員（通常為企業主或管理者）提供後台運作的可視化洞見。這有助於他們了解Line-Bot的宣傳效益，通過顯示用戶統計、趨勢和受眾分群。系統聚焦於從現有PostgreSQL資料庫進行數據視覺化，促進明智決策，而不處理核心Line-Bot邏輯。

### 1.2 範圍
系統將存取並視覺化來自現有Line-Bot後台PostgreSQL資料庫的數據。包括數據處理，如計數和過濾，以呈現有意義的視覺化。關鍵功能包括用戶註冊、數據儀表板（用戶人數、加入趨勢、回應趨勢）和受眾分群管理。系統可能需要透過生成Line message通知遠端Line-Bot系統，由其使用Line API更新分群。排除項目：系統不處理Line-Bot聊天邏輯或即時訊息；僅讀取官方帳號上的互動結果記錄。系統允許透過Line message通知僅限於分群更新操作（例如更新分群規則），不涉及聊天訊息發送或接收。每個遠端OA系統用相同格式儲存資料，提供OA名稱和URL即可存取。

### 1.3 目標用戶
- 主要用戶：Line-Bot官方帳戶架設者（例如企業主）和相關管理者。
- 存取控制：不同用戶可根據權限存取特定官方帳號的數據。支援基於角色的權限控制，例如管理員可管理普通用戶的權限（設定account_access），但自身不參與OA存取；普通用戶限特定帳號。先從後台設定哪些gmail帳號有管理者功能。權限存儲在本地PostgreSQL中，account_access 欄位為單一字串，列出可存取的Line OA名稱（對應遠端資料庫）；空白代表沒有可管理的OA帳號。

## 2. 假設與依賴

### 假設
- 遠端PostgreSQL資料庫（包含Line-Bot歷史數據）始終可用且可存取。
- 用戶擁有有效的Google帳號。
- 資料庫中的數據格式適合視覺化（例如時間戳、關鍵字）。
- 系統假設權限規則已預定義。

### 依賴
- 資料庫：遠端PostgreSQL用於Line-Bot數據（詳細欄位描述見下文）；本地PostgreSQL用於系統數據。
- 前端：React框架。
- 後端：Python Flask。
- 外部服務：Google OAuth用於註冊；遠端Line-Bot系統用於分群通知（生成Line message）。
- 硬體/軟體：標準桌面和手機網頁瀏覽器。

### 遠端PostgreSQL資料庫函式描述
後端系統不直接存取遠端PostgreSQL資料庫的資料表或視圖，而是透過呼叫兩個預先定義好的資料庫函式 (Stored Procedure) 來取得視覺化所需的數據。這種方式將複雜的資料查詢邏輯封裝在資料庫內部，簡化了後端應用程式的邏輯。

以下是這兩個函式的詳細描述：

#### 1. `get_events_count_by_category_and_tag`
- **用途**：此函式用於統計在指定時間範圍內，不同事件類別（Category）和標籤（Tag）的事件發生次數。主要用於「用戶人數和加入趨勢視覺化」(FR-002)。
- **輸入參數**：
    - `start_time` (時間戳): 查詢的開始時間。
    - `end_time` (時間戳): 查詢的結束時間。
    - `categories` (字串陣列): 要查詢的事件類別列表 (例如: `["Message", "Follow"]`)。
    - `group_unit` (字串): 時間分組單位 (例如: `"週"`, `"月"`)。
- **返回欄位**：
    - `category` (字串): 事件的類別。
    - `tag` (字串): 事件的標籤或子分類。
    - `count` (整數): 對應 `category` 和 `tag` 的事件計數。

#### 2. `get_keyword_ranking`
- **用途**：此函式用於統計在指定時間範圍內，使用者訊息中的關鍵字出現頻率排名。可選擇性地針對特定使用者標籤(tag)進行篩選。主要用於「用戶回應趨勢視覺化」(FR-003)。
- **輸入參數**：
    - `start_time` (時間戳): 查詢的開始時間。
    - `end_time` (時間戳): 查詢的結束時間。
    - `tag` (字串): 用於篩選特定使用者群組的標籤。如果為空字串，則統計所有使用者。
    - `limit` (整數): 限制回傳的關鍵字筆數。
- **返回欄位**：
    - `keyword` (字串): 使用者訊息中的關鍵字。
    - `count` (整數): 關鍵字在指定時間內出現的總次數。

視覺化功能（FR-002 和 FR-003）完全依賴這兩個函式的返回結果來繪製圖表和表格。分群管理（FR-004）的具體實作將取決於未來如何與遠端系統互動，但目前數據的讀取是基於上述函式。

## 3. 功能需求

### FR-001: 用戶認證
- **描述**：用戶使用預先登記在系統中的 Google 帳號進行登入。系統不對外開放註冊。後端會驗證用戶的 Google 帳號是否存在於系統的 `users` 資料表中，以授予存取權限。不同用戶可根據權限存取特定官方帳號的數據。
- **輸入**：Google OAuth 登入。
- **輸出**：登入成功後，取得對應權限的帳號存取能力。
- **優先級**：中（視覺化完成之後再開發）。

### FR-002: 用戶人數和加入趨勢視覺化
- **描述**：使用折線圖在儀表板格式中顯示選定時間區間的用戶人數和新加入用戶。數據來源為遠端PostgreSQL資料庫。用戶可選擇區間（週、月、年）和資料類型（訊息或加入好友）。前端負責基於查詢返回的所有群組數據進行分群顯示。
- **輸入**：時間區間選擇、資料類型選擇。
- **輸出**：顯示用戶人數和加入的互動折線圖儀表板。
- **優先級**：高（核心功能，先實現）。

### FR-003: 用戶回應趨勢視覺化
- **描述**：在選定區間顯示用戶回應的關鍵字統計。可為所有用戶或特定分群用戶（透過 `tag` 參數）排名關鍵字。數據來自遠端PostgreSQL。關鍵字排名將以表格形式呈現，包含「排名」、「關鍵字」和「次數」等欄位。關鍵字欄位有長度限制，過長的內容會以「...」顯示，滑鼠懸停時才顯示完整關鍵字。可透過 `limit` 參數控制顯示的資料筆數。
- **輸入**：時間區間、可選的 `tag` 群組過濾器、可選的 `limit` 筆數限制。
- **輸出**：一個表格，列出關鍵字及其排名和出現次數。
- **優先級**：高（核心功能，先實現）。

### FR-004: 受眾分群管理
- **描述**：允許設定自動分組規則（訊息類型 + 關鍵字）。支援新增、編輯或刪除群組和規則。從遠端更新群組列表，透過新增功能呼叫遠端進行群組更新。當本地已做修改但未進行遠端更新時，UI顯示「需按鈕完成更新」和「回復成現有狀況」兩個按鈕。透過生成Line message通知遠端Line-Bot系統，由其使用Line API進行群組和分群法則的更新。通知遠端，讓遠端自行運用。遠端系統會基於關鍵字進行分群更新。訊息類型包括「加入好友」「按下按鈕」「輸入訊息」，後兩種有訊息細節。
- **輸入**：群組標準（訊息類型 + 關鍵字，例如訊息類型「輸入訊息」關鍵字「運送」）。
- **輸出**：更新的群組列表；與視覺化整合。
- **優先級**：中（視覺化後實現）。

### FR-005: 數據匯出（未來增強）
- **描述**：允許用戶匯出視覺化數據或報告。
- **輸入**：匯出格式選擇（例如CSV、PDF）。
- **輸出**：下載的文件。
- **優先級**：低（最後實現）。

## 4. 非功能需求

### 性能
- 支援至少10個並發用戶。
- 頁面載入時間少於1秒。

### 安全性
- 敏感信息數據加密。
- 基於電子郵件的用戶身份驗證（註冊時即啟用）。

### 可用性
- 兼容標準桌面和手機網頁瀏覽器。
- 無需多語言支援。

### 其他
- 可擴展性：系統應可擴展以支援額外數據來源或功能。
- 可維護性：使用React和PostgreSQL的模組化程式碼，便於更新。
